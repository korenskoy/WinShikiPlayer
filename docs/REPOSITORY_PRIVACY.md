# Локальные данные и публикация исходников

Официальный установщик может включать общие OAuth-ключи приложения и токен Kodik с разрешения владельца. Сборщик выбирает только шесть параметров подключения из игнорируемой локальной конфигурации; сам файл не копируется в дистрибутив. Эти общие ключи извлекаемы из программы. Личные OAuth-сессии, история и ключи подписи в разрешённый список не входят. Проверка исходников по-прежнему запрещает любые реальные ключи в Git; намеренное включение ключей приложения относится только к бинарному дистрибутиву.

В Git входят исходники, тестовые ответы API с вымышленным пользователем, ресурсы интерфейса и документированная сторонняя libass.dll. Тестовые OAuth-токены — короткие заглушки. Реальные ключи в appsettings.example.json не заполняются.

В .gitignore исключены локальная конфигурация и .env, приватные ключи и сертификаты, пароли DPAPI, история, сессии, кэш, настройки пользователя, отчёты, сборки, установщики, рабочие изображения и копия macOS-проекта. Не используйте git add -f для таких файлов.

Перед коммитом:

```powershell
git add -- <нужные-файлы>
pwsh -NoProfile -File tools/Check-RepositoryPrivacy.ps1
```

Проверка экспортирует именно содержимое Git index во временный каталог внутри игнорируемого artifacts. Она запрещает приватные пути, проверяет точные совпадения с ключами из локального appsettings.local.json, допустимую стороннюю DLL по SHA-256 и запускает Gitleaks с общими и дополнительными правилами Shikimori/Kodik/OAuth. В отчётах секреты скрыты. Исходники сканируются локально.

Нужны PowerShell 7, Git и [Gitleaks](https://github.com/gitleaks/gitleaks) в PATH либо artifacts/privacy-tools/gitleaks/gitleaks.exe. При отсутствии сканера проверка завершается ошибкой. Она не загружает программы автоматически.

После клонирования включите проверку для обычных коммитов:

```powershell
git config --local core.hooksPath .githooks
```

Git hooks не включаются автоматически при клонировании. Любой локальный hook можно обойти: перед публикацией отдельно проверяйте список файлов и историю. Сканирование снижает риск, но не заменяет проверку персональных данных, изображений и содержимого новых файлов.

Подпись установщиков использует только локальные artifacts/signing. Не публикуйте PFX, пароль DPAPI или appsettings.local.json в GitHub Releases, Issues и вложениях. Публичный отпечаток сертификата в коде установщика не является приватным ключом.
